# Требования

## Назначение

Telegram-бот должен учитывать производство рейки grigliato по сменам, станкам и типам рейки. Бот считает штуки, погонные метры, заработок оператора и заработок основных наладчиков.

## Роли

- `admin` / `master`: подтверждает пользователей, управляет справочниками, смотрит отчеты.
- `operator`: работает на конкретном станке в смене.
- `setup_primary`: основной наладчик, получает долю от общей выработки всех 10 станков за смену.
- `setup_assistant`: вспомогательный наладчик, не получает расчет по выработке; в отчете отображается `Среднесдельная`.

## Смены

- Всего 4 смены: `1`, `2`, `3`, `4`.
- День: `08:00-20:00`.
- Ночь: `20:00-08:00`.
- Смена определяется автоматически по текущей дате и времени.
- Пользователь может выйти в другую смену на подработку.

Зафиксированный пример графика:

| Дата | Тип | Смена |
| --- | --- | --- |
| 25.06 | день | №4 |
| 25.06 | ночь | №3 |
| 26.06 | день | №2 |
| 26.06 | ночь | №1 |
| 27.06 | день | №2 |
| 27.06 | ночь | №1 |
| 28.06 | день | №3 |
| 28.06 | ночь | №4 |

Правило продолжения графика надо уточнить и зафиксировать алгоритмом.

## Станки

Справочник станков:

- `Г-1`
- `Г-2`
- `Г-3`
- `С-3`
- `Г-4`
- `С-1`
- `Г-6`
- `С-4`
- `С-5`
- `С-6`

## Рейки и задания

Рейка в базе должна храниться отдельно от ставок.

Поля рейки:

- полное название;
- короткое имя;
- тип, например `мама` / `папа`;
- код / артикул;
- цвет;
- металл;
- длина одной штуки в метрах;
- штук в упаковке.

Поля задания с фото или бумажного листа:

- заказчик;
- код ТС;
- тип рейки;
- цвет;
- вид металла;
- код / артикул;
- ширина;
- вес;
- общее количество штук;
- длина;
- количество упаковок;
- штук в упаковке.

## Ставки

Ставки задаются отдельно по связке `станок + рейка`, потому что одна и та же рейка может стоить по-разному на разных станках.

Поля ставки:

- станок;
- рейка;
- ставка оператора за 1000 штук;
- ставка наладчика за 1000 штук;
- дата начала действия ставки;
- дата окончания действия ставки, если ставка устарела.

## Ввод продукции

Наладчик или мастер добавляет продукцию поэтапно в течение смены:

- выбрать станок;
- выбрать рейку;
- ввести количество упаковок;
- при необходимости ввести общее количество штук из задания;
- подтвердить расчет.

Если количество штук по упаковкам и количество штук из задания отличаются, бот должен показать расхождение и спросить, какое значение принять:

- по упаковкам;
- по заданию;
- ввести вручную.

## Фото заданий

Этап 1:

- пользователь отправляет фото;
- бот сохраняет фото;
- пользователь вручную вводит данные.

Этап 2:

- бот распознает фото;
- показывает найденные значения;
- человек подтверждает или исправляет;
- только после подтверждения запись добавляется в смену.

## Отчеты

Отчет по завершению смены должен включать:

- дату;
- тип смены: день / ночь;
- номер смены;
- станки;
- операторов;
- рейки;
- упаковки;
- штуки;
- погонные метры;
- заработок оператора;
- общий заработок основных наладчиков;
- заработок каждого основного наладчика;
- для вспомогательного наладчика: `Среднесдельная`.

Отчет отправляется минимум админу/мастеру и наладчикам. Отправку операторам надо подтвердить.
